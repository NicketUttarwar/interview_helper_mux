Order interview segments into a narrative sequence for a full-length podcast master — Flow 1 (see task in volley).

- Input includes `coverage_audit`, `narrative_plan`, `gap_report`, `gap_framing_plan` (when present), `framing_covered_segment_ids`, and segment manifest.

Goals:
- Include all usable non-aside segments unless explicitly excluded with rationale.
- Order for optimal full-podcast listen — not default chronological order unless justified in `notes`.
- Satisfy every `ordering_constraints` entry from `narrative_plan`.
- Cover every topic from `coverage_audit`; do not leave brief topics unrepresented without exclude rationale.
- Preserve clarity: setup before payoff, definitions before jargon-heavy answers.
- Schedule `gap_report.interviewer_lines` implicitly (segments with VO stay in order; do not drop fixable answers).
- **Succinct master (soft hint only):** `gap_framing_plan` and `framing_covered_segment_ids` describe the **draft** framing VO, not yet accepted. Do **not** exclude a segment with `reason: covered_by_framing_vo` here — that exclusion is applied deterministically later by Refinement Pass `selection_framing_apply`, only after the framing VO is recomposed against this exact kept order (`docs/cross-cutting/refinement-passes.md`). Excluding on the draft risks stranding a segment with no surviving VO if recompose later drops or rewrites that line. You may use `framing_covered_segment_ids` only as pacing/emphasis context (e.g. deprioritizing a redundant segment for other stated reasons such as `duplicate`), never as the sole rationale.
- Trim asides only when they do not humanize the interviewee or support the thesis.
- For shard/collate runs, merge chapter or batch rankings into one `ordered_segment_ids` list, dedupe segment IDs, preserve `narrative_plan.ordering_constraints`, and keep excluded entries as objects with reasons.

Do not:
- Drop thesis-supporting `interviewee_answer` without `excluded_segment_ids` entry.
- Violate ordering_constraints.
- Output duplicate `segment_id`s in `ordered_segment_ids`.
- Output bare strings in `excluded_segment_ids`; every exclusion must be an object with `segment_id` and `reason`.

Memory sync:
- `segment_summary_patch`: `{ "master_segment_count": N, "excluded_count": N }`

Examples: see `docs/prompts/_shared/examples/full-master-ranking.examples.md`

Schema: `artifacts` → `docs/cross-cutting/json-schemas/artifacts/master_selection_artifact.schema.json`

Place this stage artifact inside the required envelope as `artifacts`:

{
  "ordered_segment_ids": ["seg_001", "seg_003", "seg_002"],
  "chapters": [
    { "title": "string", "segment_ids": ["seg_001", "seg_003"] }
  ],
  "excluded_segment_ids": [
    { "segment_id": "seg_009", "reason": "aside" }
  ],
  "notes": "optional editorial rationale"
}

Common exclusion reasons include `aside`, `duplicate`, and `low_quality`; use a concise reason string supported by the input.

## exclude rationale — required depth

Every `excluded_segment_ids[]` entry must be an object `{ "segment_id", "reason" }` with **specific** rationale:

| reason pattern | When valid |
|----------------|------------|
| `aside` | Classified `aside` or tangential; cite lack of thesis support in `notes` if contested |
| `duplicate` | Repeats claim already represented; name kept segment in reason text |
| `low_quality` | Heavy crosstalk, STT failure, or unintelligible — cite flag or transcript quality |
| `superseded` | Shorter version of same story kept elsewhere |
| `trim_for_pacing` | Rare; only when arc holds without it and `narrative_plan` allows |

**Never exclude without object rationale:**
- Thesis-supporting `interviewee_answer` with coverage_audit mapping
- Segments with scheduled `gap_report` VO fixing a `high` severity gap
- Sole segment covering a brief topic

**format_class:**
- `panel`: excluding one guest's only answer on a shared topic requires explicit duplicate or aside evidence.
- `technical_deep_dive`: keep definitional segments even if dry — exclude only with `duplicate` or `low_quality`.

**Quality bar:** `notes` summarizes editorial arc; exclusions list is auditable; zero bare segment ids; no duplicate ids in `ordered_segment_ids`.
