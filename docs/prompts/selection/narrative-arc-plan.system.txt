Plan the narrative arc for a full podcast episode before segment ordering (see task in volley).

Goals:
- Define setup → tension → payoff across interview topics.
- Use `content_brief.topic_relationships` (when present) to inform `ordering_constraints` and chapter flow.
- Propose chapter boundaries (title + `suggested_open_segment_id` that exists in manifest).
- Output `ordering_constraints`: pairs that must appear in relative order.
- Do not exclude segments — ranking stage applies cuts.
- At most `max_chapters` chapters (see pipeline thresholds).
- Every `ordering_constraints` item must use real `segment_id`s from input. Use an empty array only when no ordering constraint is supported by evidence.

Do not:
- Reference segment_ids not in input manifest.
- Plan chronological-only arc without editorial reason.

Memory sync:
- `narrative_patch`: refine `thesis` if arc reveals a sharper through-line

Examples: see `docs/prompts/_shared/examples/narrative-arc-plan.examples.md`

Schema: `artifacts` → `docs/cross-cutting/json-schemas/artifacts/narrative_plan_artifact.schema.json`

Place this stage artifact inside the required envelope as `artifacts`:

{
  "arc_summary": "one paragraph",
  "chapters": [
    { "chapter_id": "ch_01", "title": "string", "topic_tags": [], "suggested_open_segment_id": "seg_001" }
  ],
  "ordering_constraints": [
    { "before_segment_id": "seg_010", "after_segment_id": "seg_003", "reason": "setup before payoff" }
  ],
  "pacing_notes": "string"
}

## ordering_constraints — evidence and format_class

`ordering_constraints` encode **editorial causality**, not recording order:

- **Prerequisite topics:** If topic B depends on A in `topic_relationships`, constrain opening segment of B after closing segment of A (use real `segment_id`s from manifest).
- **Definition before use:** Jargon-heavy `interviewee_answer` after `missing_definition` risk → constrain defining `setup` or earlier answer segment before dependent segment.
- **Payoff after tension:** `emotional_beats` with `tension` before `triumph` when both exist — cite beat labels in `reason`.
- **Panel:** Allow interleaved guests in recording order unless `returns_to` relationship requires callback segment after all guest threads introduced.
- **Debate:** Constrain rebuttal segments after the claim they address when `evidence_segment_ids` support linkage.

Each constraint needs:
- `before_segment_id` — must appear **earlier** in planned arc than `after_segment_id` (narrative order, not timecode).
- `reason` — one concrete editorial sentence; no "because better flow" without causal claim.

Empty array is valid only when manifest lacks supporting relationships **and** chronological order is editorially defensible in `arc_summary`.

**Quality bar:** Every chapter `suggested_open_segment_id` exists in input; constraints must survive full master ranking — do not over-constrain if evidence supports only one ordering.

## coherence_summary — drift hinges

When `coherence_summary.risks` includes `topic_drift`, prefer chapter boundaries near those `time_ms` values and note drift in `arc_summary` constraints when reordering would hide a thematic return.
