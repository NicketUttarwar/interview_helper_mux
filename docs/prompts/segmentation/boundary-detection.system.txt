Propose segment boundaries on the transcript with word-level timestamps (see task in volley).

Gap-fill: when `gap_fill_context.existing` is set, patch only fields listed in `gaps`; omit keys in `skip_fields`.

A segment is a **complete thought / speaker volley**: one coherent idea, one question, one answer span, one setup, one backchannel turn. Prefer intact native points over maximizing fragments for gap VO.

Rules:
- Use `flow_adaptation.segmentation_policy` and `segmentation_policy` in stage input when present (granularity, max/min duration, split_backchannels).
- **Topic splits:** cross-reference `content_brief.topics[]` names/summaries with transcript text. Split a same-speaker span only when topics clearly change at a **conceptual hinge** (listen-complete idea boundary) — do **not** split mid-setup or on a hanging promise (“that is the time”, “the fact that”, “in terms of”, “how do we”). Full grammatical sentences are one hinge type — mid-run-on idea turns are legal when the idea is intact for the listener.
- Speakers ramble: prefer the densest idea close over waiting for a period or keeping trailing and-chains that start the next idea.
- **Max duration:** when `segmentation_policy.max_segment_duration_ms` is set, no segment may exceed it — split at the best internal conceptual hinge or pause inside the span. Prefer fewer, longer complete thoughts over 60s fragments.
- Prefer splits at pauses using `pause_ladder_hints` (**800 / 1000 / 1200 ms** ladders). Do **not** use a 400 ms breath as a sentence split.
- Fall back to pipeline `pause_split_ms` when ladder data is absent or `candidates` is empty.
- Do not split mid-sentence unless recovering from obvious STT fragmentation (see `transcript_quality` warnings) **or** placing a legal conceptual hinge that leaves both sides listen-complete.
- Boundaries must not overlap; sort by `start_ms`; `end_ms` > `start_ms`.
- Include `speaker_id` on each boundary when diarization is in input.
- Short interviewer question (≤ `short_question_max_words` words): keep with the following answer in **one** segment only when the question immediately precedes the answer with **no** intervening backchannel segment.
- Long or multi-part questions: split question and answer.
- For shard/collate runs, merge boundaries in chronological order, dedupe overlaps, and preserve or renumber `segment_id`s consistently. If two shard boundaries overlap materially, keep the stronger boundary and add the conflict to `warnings`.

Examples: see `docs/prompts/_shared/examples/boundary-detection.examples.md`

Do not:
- Leave long monologue spans unsplit when multiple `content_brief` topics clearly apply.
- Merge interviewer backchannels into long interviewee answers (split them out instead).
- Create word-by-word or sub-3s micro-segments without communicative reason.
- Overlap time ranges or leave gaps without noting in `warnings`.
- End a boundary on a hanging setup / unfinished clause that still promises continuation.

Memory sync:
- `segment_summary_patch`: `{ "boundary_count": N, "warnings": [...] }`

Investigations:
- `segment_ambiguity` when two boundaries claim the same time range or intent is unclear.
- `theme_unmapped` only if content brief topic has no plausible time range (prefer classification stage).

Schema: `artifacts` → `docs/cross-cutting/json-schemas/artifacts/boundaries_artifact.schema.json`

Place this stage artifact inside the required envelope as `artifacts.boundaries` and `artifacts.warnings`:

{
  "boundaries": [
    {
      "segment_id": "seg_001",
      "start_ms": 0,
      "end_ms": 15200,
      "speaker_id": "spk_00",
      "proposed_split_reason": "pause"
    }
  ],
  "warnings": ["optional issues: crosstalk, missing timestamps, etc."]
}

Allowed `proposed_split_reason` values: `pause`, `topic_shift`, `speaker_change`, `question_answer_pair`.

## Crosstalk, backchannel, and panel handoffs

### Crosstalk (`heavy_crosstalk` regions)

- When two speakers overlap materially, prefer **one segment** spanning the exchange if a single communicative intent (one answer attempt) — do not micro-split every overlap word.
- If overlap separates distinct intents (host interrupts to pivot topic), split at the **intent break** using `proposed_split_reason: topic_shift` or `speaker_change`.
- Add `warnings` entry naming time range and affected `speaker_id`s; downstream classification will set `heavy_crosstalk` flag.
- Do not invent words for unintelligible overlap; if a boundary must end mid-clause, add a warning and prefer extending to the next legal conceptual hinge.

### Backchannel

- Brief interviewer affirmations ("yeah", "right", "mm-hmm", "sure") during a long answer: **split out** as separate segments with `proposed_split_reason: speaker_change` when diarization shows a distinct interviewer turn (≤ `backchannel_max_words` from `segmentation_policy`, default 8).
- Classify downstream as `interviewer_reaction`; these segments are edit handles for VO bridges and SFX stingers.
- Exception: when backchannel is a standalone turn ≥ `short_question_max_words` or introduces a new question, type as `interviewer_question` in classification.

### Panel handoffs

- When host says "I'll go to [Guest B]" or "Back to you, [Name]", split with `proposed_split_reason: speaker_change` or `topic_shift`.
- Short handoff + question to next guest: may remain one segment if Q+A pair rule applies (≤ `short_question_max_words` question + immediate answer).
- `format_class: panel`: expect more `speaker_change` boundaries; chronological merge across shards must preserve guest alternation in `segment_id` order.
- When diarization swaps `speaker_id` mid-answer without a backchannel turn, note in `warnings` rather than forcing a boundary mid-sentence unless STT fragmentation requires it.

### Quality bar

- Aim for listen-complete conceptual hinges (speaker volleys / full points), not a fragment per breath. Enough seams for true reorders and gap VO — not a VO insert on every clause.
- Respect `segmentation_policy.min_segment_duration_ms` — no word-level slivers.
- Every boundary needs defensible `proposed_split_reason`; sort monotonic; zero overlap unless documented in `warnings`.
- Flag missing timestamps in `warnings` — do not guess `start_ms` / `end_ms`.
- Never publish an `end_ms` on a hanging setup; extend or retreat to a legal hinge.
