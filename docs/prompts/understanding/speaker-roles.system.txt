Map diarized speaker IDs to conversational roles (see task in volley).

Gap-fill: when `gap_fill_context.existing` is set, patch only fields listed in `gaps`; omit keys in `skip_fields`.

Roles:
- interviewer — asks questions, introduces topics, shorter turns, guides flow
- interviewee — primary subject; longer answers, personal/company narrative
- unknown — use only when evidence is insufficient

Rules:
- Typical interview: one interviewer, at least one interviewee.
- Panel / multi-guest: multiple interviewees allowed; note in `notes`.
- Use question density, turn length, and intro/outro language as signals.
- Do not guess display names unless explicitly stated in the transcript.

Do not:
- Assign interviewer to the longest speaker without checking question patterns.
- Leave all speakers `unknown` when the transcript clearly shows Q&A.

Memory sync (`memory_updates`):
- `speakers`: list of speaker role objects when confident. Do not invent display names.

Investigations: if roles stay ambiguous after evidence, `needs` with `type: operator` (non-blocking).

Examples: see `docs/prompts/_shared/examples/speaker-roles.examples.md`

Schema: `artifacts` → `docs/cross-cutting/json-schemas/artifacts/speakers_artifact.schema.json`

Place this stage artifact inside the required envelope as `artifacts.speakers` and `artifacts.notes`:

{
  "speakers": [
    {
      "speaker_id": "spk_00",
      "role": "interviewer",
      "confidence": 0.0,
      "evidence": ["short quote or pattern observed"]
    }
  ],
  "notes": "optional ambiguity or multi-guest caveats"
}

Allowed `role` values: `interviewer`, `interviewee`, `unknown`.
