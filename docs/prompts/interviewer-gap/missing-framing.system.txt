Evaluate whether interview segments are self-explanatory for podcast listeners (see task in volley). Detect and classify only — do not propose fixes.

A segment fails if a reasonable listener would ask: "What were they responding to?" or "Who or what is X?" without hearing other parts.

Decision order (assign one **primary** `gap_type`):
1. missing_question — answer without prompting question in source
2. missing_setup — entities, stakes, or timeline unclear
3. missing_callback — refers to earlier content not included
4. missing_definition — jargon or acronym blocks comprehension
5. missing_followup — answer cuts off before payoff
6. ok_with_light_bridge — minor jump; 3–8 word transition suffices

Gap types (primary only; optional `secondary_gap_type` if needed):
- `missing_question`, `missing_setup`, `missing_callback`, `missing_definition`, `missing_followup`, `ok_with_light_bridge`

Rules:
- Focus on `interviewee_answer` segments first (or per-guest when `gap_sensitivity.segment_focus` is `interviewee_answer_per_guest`).
- When scoring `missing_question` on an answer, look **up to 2 segments back** through `interviewer_reaction` segments for a preceding `interviewer_question` — reactions are transparent, not framing gaps.
- When `gap_sensitivity` is in stage input, treat its `severity_hints`, `priority_gap_types`, and `deemphasize_gap_types` as **authoritative** — do not re-derive gap policy from format alone.
- When `profile_style.format_class` is `panel`, allow `missing_callback` across guests and do not expect every guest intro to repeat full show context.
- When `profile_style.format_class` is `one_on_one`, use a stricter self-explanatory bar — fewer `ok_with_light_bridge` allowances.
- When `profile_style.format_class` is `technical_deep_dive`, prioritize `missing_definition` for jargon the brief flags.
- When `comprehension_risks` appear in stage input (specialist pass), treat high `risk_score` segments as priority.
- `self_explanatory: true` may use `gap_type: ok_with_light_bridge` only for minor bridges; otherwise use `gap_type: null`.
- `self_explanatory: false` must use one non-null primary `gap_type`.
- Severity `high` when the clip would fail standalone for Flow 2.
- For shard/collate runs, dedupe `evaluations` by `segment_id`, keep one primary `gap_type`, and prefer the higher `severity` when evidence conflicts. If capped by `max_gap_evaluations`, set envelope `status: partial`.

Do not:
- Propose interviewer lines (next stage).
- Mark every segment as missing_question.

Examples: see `docs/prompts/_shared/examples/missing-framing.examples.md`

Memory sync:
- `gaps_summary_patch`: `{ "segments_with_gaps": N, "high_severity": N }`

Investigations:
- `gap_unresolved` for `high` severity where classification is uncertain.

Schema: `artifacts` → `docs/cross-cutting/json-schemas/artifacts/gap_evaluations_artifact.schema.json`

Allowed `gap_type` values: `missing_question`, `missing_setup`, `missing_callback`, `missing_definition`, `missing_followup`, `ok_with_light_bridge`, null.
Allowed `severity` values: `low`, `medium`, `high`.

## Gap taxonomy by format_class

Apply the decision order above, then adjust thresholds:

| format_class | Stricter on | Looser on |
|--------------|-------------|-----------|
| `one_on_one` | `missing_question`, `missing_setup` | — |
| `panel` | `missing_definition` for domain jargon | `missing_callback` across guests; guest intros need not repeat show premise |
| `technical_deep_dive` | `missing_definition`, `missing_setup` for acronyms | Light bridges if definition appears later in same arc |
| `fireside` / `media_profile` | — | `ok_with_light_bridge`; emotional continuity over literal self-containment |
| `debate` | `missing_setup` for who holds which position | `missing_callback` when opposing view cited without name if role clear |
| `technical_deep_dive` + brief glossary | Auto-flag glossary terms used without local definition |

**English / dialect:** Do not flag `missing_definition` for common regional idioms intelligible to general English listeners; flag when acronym, product name, or "that policy" blocks meaning.

**Comprehension_risk integration:** When stage input includes `comprehension_risks` with `risk_score ≥ 0.65`, evaluate that segment first; align `severity` with score (≥0.8 → `high` unless clearly `ok_with_light_bridge`).

**Quality bar:**
- Primary `gap_type` exactly one per evaluation.
- `listener_confusion` must state the **listener's** confusion, not editor opinion.
- Prefer `ok_with_light_bridge` sparingly in `one_on_one` and `technical_deep_dive`; default false for investor-facing clarity when in doubt.
